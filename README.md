# motion-align

Siamese-embedding + DTW temporal alignment for motion-capture
performances.

## Setup

```bash
pip install -r requirements.txt
```

`fvcore` (FLOPs counting) and `torch-dct` (PoseFormerV2's frequency
branch) are the two non-obvious dependencies beyond PyTorch/numpy/scipy.

## Data prep

`data/` and `outputs/` are gitignored (multi-GB of mocap patches and run
artifacts don't belong in git). Expected layout once populated:

```
data/
  Patches/             # full eval patch set, 100 performances (~3 GB)
  TrainPatches/         # 20-take training subset (~707 MB)
  eval/
    tmm100performances.mat
    tmmkeyposes.mat
```

Everything under `data/` is generated by this repo's own code, from two
inputs: the raw PSU-TMM100 mocap marker data, and `assets/keyposes.csv`
(manually-annotated keypose frame numbers, all 45 pose classes).

```bash
cd src/data_prep

# Patches/ + TrainPatches/, extracted from raw MOCAP_MRK_<take>.npy files
python generate_patch_dataset.py \
    --raw-root /path/to/PSU_NPY/Subject_wise \
    --patches-out ../../data/Patches \
    --trainpatches-out ../../data/TrainPatches

# eval/tmm100performances.mat + eval/tmmkeyposes.mat, from the raw data
# listing + keyposes.csv (43 of the 45 classes are used -- classes 33 and
# 35 are merged into their neighboring same-pose classes)
python generate_eval_reference.py \
    --raw-root /path/to/PSU_NPY/Subject_wise \
    --keyposes-csv ../../assets/keyposes.csv \
    --out-dir ../../data/eval
```

`extract_mocap_patches.py` is the underlying single-take extraction
function both scripts build on, useful for inspecting one take directly:

```bash
python extract_mocap_patches.py <path-to-MOCAP_MRK_N.npy> <output.npz>
```

The default `--patch-dir`, `--tmm100`, and `--keyposes` flags on the
evaluation scripts all point at the `data/` locations above.

## Usage

### Step A — Train + evaluate end-to-end with PyTorch

```bash
cd src/evaluation
python run_figure6.py \
    --train \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --epochs 38 \
    --output-dir ../../outputs/run1
```

### Step B — Evaluate an already-trained model

```bash
python run_figure6.py \
    --model ../../outputs/run1/phase1/model.pt \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/run1
```

## Ablations

Each ablation swaps the Siamese encoder via `--encoder
{cnn,poseformer,mixste,poseformerv2}` and runs the same three-stage
pipeline: **(1)** Phase-1 LOO-10 training, **(2)** DTW alignments against
the atlas, **(3)** keypose-transfer ROC. All three stages are driven by
`run_figure6_ablation.py`; the script lives under `src/evaluation/`
because the ROC evaluation is the final stage and the orchestrator's
output is the ROC curve, but `--train` makes it train first. Pass
`--model <path>` instead of `--train` to skip stage 1 and reuse a
trained checkpoint.

Per-encoder source files (under `src/`):
- `model.py` — CNN baseline (371 K params, 2.3 M FLOPs/sample)
- `model_poseformer.py` — PoseFormer (50 M params, 3.9 G FLOPs)
- `model_mixste.py` — MixSTE (34 M params, 101 G FLOPs)
- `model_poseformerv2.py` — PoseFormerV2 (76 M params, 2.8 G FLOPs)

### Run commands

From the repo root:

```bash
cd src/evaluation

# CNN baseline
python -u run_figure6_ablation.py --train --encoder cnn --seed 0 --epochs 38 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/cnn_ablation

# PoseFormer
python -u run_figure6_ablation.py --train --encoder poseformer --seed 0 --epochs 38 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/poseformer_ablation

# PoseFormerV2
python -u run_figure6_ablation.py --train --encoder poseformerv2 --seed 0 --epochs 38 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/poseformerv2_ablation

# MixSTE
python -u run_figure6_ablation.py --train --encoder mixste --seed 0 --epochs 38 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/mixste_ablation
```

Each run streams both the orchestrator's output and the training
subprocess's combined stdout/stderr to
`<output-dir>/logs/<encoder>_<YYYYMMDD_HHMMSS>.log`, so failures in any
stage (including the Phase-1 training subprocess) are captured to disk.
The same output is mirrored to the terminal -- no `tee /tmp/...`
redirection needed.

`--tmm100` and `--keyposes` default to `../../data/eval/...` so they no
longer need to be passed.

### Per-encoder original optimizer recipes

By default every encoder is trained with the CNN baseline's recipe
(`SGD`, `lr=0.01/batch_size`, `weight_decay=5e-4`, no LR decay) so the
ablation is apples-to-apples on optimization. To instead train each
non-CNN encoder with the optimizer + LR + weight-decay + per-epoch LR
decay from its **original paper / reference implementation**, pass
`--use-original-hparams`. The presets (sourced from each method's own
original training recipe) are:

| encoder        | optimizer | lr     | weight_decay | per-epoch lr_decay |
|----------------|-----------|--------|--------------|--------------------|
| `cnn`          | SGD       | 0.01 / batch_size | 5e-4 | 1.0  |
| `poseformer`   | AdamW     | 1e-4   | 0.1          | 0.99               |
| `poseformerv2` | AdamW     | 1e-4   | 0.1          | 0.99               |
| `mixste`       | AdamW     | 4e-5   | 0.1          | 0.99               |

Two extra orchestrator flags are also useful here:
- `--num-workers N` — DataLoader workers for the Phase-1 loaders (the
  default `0` matches the original code; bump to e.g. `4` to overlap CPU
  pre-fetching with GPU compute).
- `--epochs` is hard-capped at `50` by the orchestrator.

```bash
cd src/evaluation

# PoseFormer with its own AdamW / 1e-4 / wd=0.1 / 0.99 lr-decay recipe
python -u run_figure6_ablation.py --train --encoder poseformer --seed 0 \
    --epochs 50 --use-original-hparams --num-workers 4 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/poseformer_ablation_orig

# PoseFormerV2 with its own AdamW / 1e-4 / wd=0.1 / 0.99 lr-decay recipe
python -u run_figure6_ablation.py --train --encoder poseformerv2 --seed 0 \
    --epochs 50 --use-original-hparams --num-workers 4 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/poseformerv2_ablation_orig

python -u run_figure6_ablation.py --train --encoder mixste --seed 0 \
    --epochs 50 --use-original-hparams --num-workers 4 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/mixste_ablation_orig
```

The full resolved hyperparameters end up in
`<output-dir>/phase1/benchmarks.json` (`optimizer`, `lr`, `lr_effective`,
`lr_decay`, `weight_decay`, `use_original_hparams`, `num_workers`).

```bash
# If NVML is failing
env PYTORCH_NO_CUDA_MEMORY_CACHING=1 \
    python -u run_figure6_ablation.py --train --encoder mixste --seed 0 \
    --epochs 50 --use-original-hparams --num-workers 4 \
    --train-data-dir ../../data/TrainPatches \
    --patch-dir ../../data/Patches \
    --output-dir ../../outputs/mixste_ablation_orig
```

### Outputs

Each `outputs/<encoder>_ablation/` directory contains:
- `phase1/model.pt`, `phase1/benchmarks.json` — trained encoder + train-time
  param counts, FLOPs, and per-epoch timing.
- `MyMocapAlignments.mat` — DTW alignments against the atlas.
- `alignment_benchmarks.json` — inference timings + FLOPs.
- `MyMocapKeyposeaccuracy_<encoder>.{png,eps}` — ROC curve figure.
- `MyMocapKeyposeaccuracy_<encoder>_roc.npz` — raw ROC numerics
  (thresholds, counts, per-keypose errors, per-subject errors, AUC) so the
  curve can be redrawn (or bootstrap-STD shaded) without rerunning anything.
- `mocapErrors.mat` — per-keypose absolute frame errors.
- `ablation_summary.json` — combined summary of all three stages.
- `logs/<encoder>_<YYYYMMDD_HHMMSS>.log` — full captured stdout/stderr
  of the orchestrator and the Phase-1 training subprocess.
