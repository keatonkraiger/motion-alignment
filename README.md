# motion-align

Siamese-embedding + DTW temporal alignment for motion-capture
performances.

## Setup

```bash
pip install -r requirements.txt
```

`fvcore` (FLOPs counting) and `torch-dct` (PoseFormerV2's frequency
branch) are the two non-obvious dependencies beyond PyTorch/numpy/scipy.

## Layout

```
src/
  train.py               # the one entry point: YAML config in, trained model + ROC curve out
  benchmark.py             # shared timing / FLOPs / param-count utilities
  models/
    __init__.py             # build_model(name, params) registry
    cnn.py, poseformer.py, mixste.py, poseformerv2.py
    loss.py                 # CrossCorrLoss
  data/
    datasets.py              # patch loading (ALL_TAKES, load_take, load_subject, ...)
    extract_mocap_patches.py # raw mocap -> normalized 3-second patches (single take)
    generate_patch_dataset.py   # batch-runs the above over the whole PSU-TMM100 set
    generate_eval_reference.py  # builds tmm100performances.mat + tmmkeyposes.mat
  evaluation/
    alignments.py             # phase 2: DTW-align every performance against the atlas
    keypose_eval.py            # ROC curve + AUC (this *is* "figure 6" -- no separate step)
    dtw.py, valid_performances.py, plot_combined_roc.py

configs/
  cnn.yaml, poseformer.yaml, mixste.yaml, poseformerv2.yaml

assets/
  keyposes.csv              # manually-annotated keypose frame numbers (all 45 pose classes)
  taiji_classnames.json      # class_index -> pose name, for keyposes.csv

data/        # gitignored -- see "Data prep" below
outputs/     # gitignored -- run artifacts land here
```

## Data prep

Everything under `data/` is generated by this repo's own code, from two
inputs: the raw PSU-TMM100 mocap marker data, and `assets/keyposes.csv`.
Expected layout once populated:

```
data/
  Patches/             # full eval patch set, 100 performances (~3 GB)
  TrainPatches/         # 20-take training subset (~707 MB)
  eval/
    tmm100performances.mat
    tmmkeyposes.mat
```

```bash
cd src/data

# Patches/ + TrainPatches/, extracted from raw MOCAP_MRK_<take>.npy files
python generate_patch_dataset.py \
    --raw-root /path/to/PSU_NPY/Subject_wise \
    --patches-out ../../data/Patches \
    --trainpatches-out ../../data/TrainPatches

# eval/tmm100performances.mat + eval/tmmkeyposes.mat, from the raw data
# listing + keyposes.csv (43 of the 45 classes are used -- classes 33 and
# 35 are merged into their neighboring same-pose classes)
python generate_eval_reference.py \
    --raw-root /path/to/PSU_NPY/Subject_wise \
    --keyposes-csv ../../assets/keyposes.csv \
    --out-dir ../../data/eval
```

`extract_mocap_patches.py` is the underlying single-take extraction
function both scripts build on, useful for inspecting one take directly:

```bash
python extract_mocap_patches.py <path-to-MOCAP_MRK_N.npy> <output.npz>
```

## Usage

Everything runs through `src/train.py` and a YAML config -- there's no
separate "evaluate" or "generate figure 6" script. A config names the
model (+ its architecture params), the data paths, the training
hyperparameters, and which phase(s) to run:

* **Phase 1** -- train the Siamese encoder (LOO-10: held out subject 10).
* **Phase 2** -- DTW-align every performance in `data/Patches` against a
  fixed atlas performance using the trained encoder, then run the
  keypose-transfer evaluation. The ROC curve and AUC are simply what
  phase 2's evaluation produces -- not a separate step.

```bash
# Both phases, using configs/cnn.yaml as-is
python src/train.py configs/cnn.yaml

# Just train
python src/train.py configs/poseformer.yaml --phase 1

# Just evaluate an existing checkpoint
python src/train.py configs/mixste.yaml --phase 2 \
    --model outputs/mixste_ablation/phase1/model.pt

# All four encoders
for cfg in cnn poseformer mixste poseformerv2; do
    python src/train.py configs/$cfg.yaml
done
```

Run from the repo root (the configs' data/output paths are relative to
it). Each encoder's config lives at `configs/<encoder>.yaml`:

```yaml
model:
  name: poseformer
  params: {embed_dim_ratio: 32, depth: 4, num_heads: 8, ...}  # architecture

phase: both          # "1", "2", or "both"
seed: 0
output_dir: outputs/poseformer_ablation

data:
  train_patches_dir: data/TrainPatches
  patches_dir: data/Patches
  tmm100_path: data/eval/tmm100performances.mat
  keyposes_path: data/eval/tmmkeyposes.mat

training:
  epochs: 38
  batch_size: 128
  optimizer: SGD          # CNN-baseline recipe by default (apples-to-apples ablation)
  lr: 0.01
  weight_decay: 0.0005
  lr_decay: 1.0
  use_original_hparams: false  # true -> use this encoder's own paper recipe instead

evaluation:
  atlas_subject: 7
  atlas_take: 2
```

Per-encoder architectures (under `src/models/`):
- `cnn.py` — CNN baseline (371 K params, 2.3 M FLOPs/sample)
- `poseformer.py` — PoseFormer (50 M params, 3.9 G FLOPs)
- `mixste.py` — MixSTE (34 M params, 101 G FLOPs)
- `poseformerv2.py` — PoseFormerV2 (76 M params, 2.8 G FLOPs)

### Original per-encoder optimizer recipes

By default every encoder trains with the CNN baseline's SGD recipe so
ablations are apples-to-apples on optimization. Set
`training.use_original_hparams: true` in a config to instead use that
encoder's own paper/reference-implementation recipe:

| encoder        | optimizer | lr     | weight_decay | per-epoch lr_decay |
|----------------|-----------|--------|--------------|--------------------|
| `cnn`          | SGD       | 0.01 / batch_size | 5e-4 | 1.0  |
| `poseformer`   | AdamW     | 1e-4   | 0.1          | 0.99               |
| `poseformerv2` | AdamW     | 1e-4   | 0.1          | 0.99               |
| `mixste`       | AdamW     | 4e-5   | 0.1          | 0.99               |

(presets live in `ORIGINAL_HPARAMS` in `src/models/__init__.py`).
`training.epochs` is capped at 50 by `train.py`.

### Outputs

Each `output_dir` (e.g. `outputs/cnn_ablation/`) contains:
- `phase1/model.pt`, `phase1/model_state_dict.pt`, `phase1/benchmarks.json`,
  `phase1/loss_plot.png` — trained encoder + param counts, FLOPs, timing.
- `MyMocapAlignments.mat` — DTW alignments against the atlas.
- `alignment_benchmarks.json` — inference timings + FLOPs.
- `MyMocapKeyposeaccuracy_<encoder>.{png,eps}` — the ROC curve.
- `MyMocapKeyposeaccuracy_<encoder>_roc.npz` — raw ROC numerics
  (thresholds, counts, per-keypose errors, per-subject errors, AUC) so the
  curve can be redrawn without rerunning anything.
- `mocapErrors.mat` — per-keypose absolute frame errors.
- `run_summary.json` — combined summary of both phases.
- `train.log` — full captured log of the run (overwritten on rerun).
